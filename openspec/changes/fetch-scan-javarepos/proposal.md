# Proposal

## Why

У пользователя есть несколько Java-репозиториев, в которых регулярно появляются уязвимые зависимости из-за обновления сторонних библиотек. Текущий процесс ручного анализа требует времени эксперта на каждый репозиторий — сканирование, проверка каждой уязвимости и обоснование её применимости к конкретному коду. Этот процесс не масштабируется при росте числа проектов и количества обновлений.

Необходимо автоматизировать первичный этап — получение актуального кода и его сканирование на уязвимости — чтобы исключить рутину и подготовить данные для последующего AI-анализа.

## What Changes

- **Автоматическое получение кода** — приложение будет самостоятельно клонировать и обновать Java-репозитории по заданному расписанию, без участия человека
- **Запуск SCA-сканирования** — после получения актуального кода система проверит все зависимости (включая транзитивные) на известные уязвимости через OWASP Dependency Check
- **Сохранение результатов** — сканированные данные будут записаны в структурированном виде для последующей обработки AI-агентом

Результат этого этапа — готовый набор данных с перечнем найденных уязвимостей по каждому репозиторию. AI-обоснование applicability находится за рамками этого slice.

## Capabilities

### New Capabilities
- `repo-scan`: Периодическое обновление Java-репозиториев и выполнение SCA-сканирования на уязвимые зависимости с сохранением структурированных результатов

## Impact

- **Новая функциональная область:** SCA-сканирование добавляется как отдельный модуль к существующему агенту; логика сканирования полностью изолирована от AI-компонента
- **Инфраструктура:** потребуются дополнительные ресурсы на VM (Java Runtime, свободное место под кеш репозиториев)
- **Конфигурация:** необходимо определить список сканируемых репозиториев и параметры сканирования в конфигурационном файле
